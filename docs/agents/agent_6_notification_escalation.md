# Agent 6: Notification & Escalation Engine — Architectural Specification

## 1. Executive Summary & Purpose

**Agent 6 (Notification & Escalation Engine)** is an event-driven operational agent in FinanceFlow AI responsible for real-time risk alerts, SLA breach tracking, borrower delinquency notifications, and multi-tier organizational escalations.

Rather than sending passive bulk alerts, Agent 6 evaluates financial severity, borrower delinquency history, and organizational roles to route actionable alerts to the appropriate stakeholders (**Senior Accountants**, **Finance Managers**, or **Executive Directors**).

```text
                  FINANCEFLOW EVENT BUS / AUDIT STREAM
                                   │
                   ┌───────────────┼───────────────┐
                   ↓                               ↓
          Scheduled SLA Monitor          Manual / AI Trigger
                   │                               │
                   └───────────────┬───────────────┘
                                   ↓
                  AGENT 6: NOTIFICATION & ESCALATION
                                   │
         ┌─────────────────────────┼─────────────────────────┐
         ↓                         ↓                         ↓
   TIER 1: OPERATIONAL       TIER 2: MANAGEMENT        TIER 3: EXECUTIVE
   (Unmatched Payments)      (High-Risk Delinquency)   (Severe Default SLA)
         │                         │                         │
         ↓                         ↓                         ↓
   Socket.IO Alerts          Action Center Drawer      System Broadcast
```

## 2. Escalation Tiers & Routing Matrix

| Tier | Severity Level | Target Audience | Trigger Conditions | Action Protocol |
| :--- | :--- | :--- | :--- | :--- |
| **Tier 1** | `LOW` / `MEDIUM` | Senior Accountants | New un-reconciled payment ingested, confidence score < 85% | In-app notification bell + live toast notification |
| **Tier 2** | `HIGH` | Finance Managers | Overdue installment > 15 days, aggregate borrower exposure > ₹5 Lakhs | Escalation queue in Action Center + WebSocket alert |
| **Tier 3** | `CRITICAL` | Executive Leadership | Overdue installment > 45 days, loan facility default flag, repeated payment failure | High-priority modal broadcast + persistent audit log flag |

## 3. Core Triggers & Event Lifecycle

### A. Automatic Scheduled SLA Trigger
- Scans `repayment_schedules` where `due_date < CURDATE()` and `status NOT IN ('paid', 'cancelled')`.
- Evaluates days overdue:
  - 1–14 days: Marks priority as `MEDIUM`.
  - 15–44 days: Marks priority as `HIGH` and dispatches Tier 2 escalation.
  - 45+ days: Marks priority as `CRITICAL` and dispatches Tier 3 emergency broadcast.

### B. Copilot Human-in-the-Loop Trigger (`proposeEscalateAlert`)
- Triggered by user request in the AI Copilot: *"Escalate this case to the finance manager"*.
- AI generates a proposal (`ACT-XXXXXX`), validated and confirmed by human before emission.

## 4. WebSocket & REST Schema

### Socket.IO Event Schema
- **Event Name**: `notification:alert`
- **Payload**:
```json
{
  "id": "NOTIF-1787123984",
  "title": "🚨 Urgent Escalation (MANAGER) — Case #16",
  "message": "Transaction ID mismatch and overdue payment of ₹1,00,000 requires immediate sign-off.",
  "type": "urgent",
  "case_id": 16,
  "created_at": "2026-08-21T07:15:00.000Z"
}
```

### Database Persistence
All notifications and agent runs are tracked in:
- `agent_runs` (Agent ID: `agent_6_notification`)
- `agent_execution_logs` (Step-by-step dispatch audit trail)
- `audit_logs` (User confirmations and escalation mutations)

---

## 5. Security & RBAC Constraints
1. Only users with `manager` or `admin` roles can acknowledge or resolve Tier 2/Tier 3 escalations.
2. Escalations generated by the AI Assistant must follow the **Action Proposal Protocol** (mandatory human confirmation).
