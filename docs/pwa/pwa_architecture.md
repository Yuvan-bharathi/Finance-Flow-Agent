# FinanceFlow AI — PWA Architecture Specification

## 1. Architectural Overview

FinanceFlow AI is an enterprise financial operations platform utilizing an **online-first, single-source-of-truth architecture**. The Progressive Web App (PWA) extends the full desktop financial operations suite into a mobile-first command center without creating duplicate pipelines or compromising ledger integrity.

```text
                    FINANCEFLOW AI BACKEND (Node.js + Express)
                                    │
                     ┌──────────────┴──────────────┐
                     │                             │
               Desktop Web                        PWA
            (Operations Center)          (Mobile Command Center)
                     │                             │
                     └──────────────┬──────────────┘
                                    │
                             Same AI Services
                                    │
               ┌──────────┬─────────┼─────────┬──────────┐
               │          │         │         │          │
            Copilot    Agent 1   Agent 2   Agent 3 ... Agent 6
               │
               └─────────── MySQL + Audit Log + RBAC
```

## 2. Core PWA Components & Lifecycle

### 2.1 Web App Manifest
Configured via `vite-plugin-pwa` in `frontend/vite.config.js`:
- **Application Name**: `FinanceFlow AI — Agentic Financial Operations Platform`
- **Short Name**: `FinanceFlow AI`
- **Display Mode**: `standalone` (seamless native application experience)
- **Orientation**: `portrait-primary`
- **Theme Color**: `#4f46e5` (Primary Indigo)
- **Background Color**: `#0b0f17` (Deep Slate / Dark Surface)
- **Start URL & Scope**: `/`
- **Icon Assets**: 192x192 PNG, 512x512 PNG, 512x512 Maskable PNG, 180x180 Apple Touch Icon.

### 2.2 Service Worker Engine (Workbox)
- **Safe Static App Shell Caching**: Automatically pre-caches HTML, bundled JavaScript, CSS, typography fonts (Google Fonts Inter / Outfit), and brand SVG/PNG assets.
- **Strict Network-Only Boundary**: All backend API requests (`/api/*`) are configured with `NetworkOnly` strategy. Zero financial records or AI responses are cached offline.
- **No Automatic Queueing**: Background synchronization of write operations is strictly disabled to prevent replay attacks, out-of-order execution, and stale financial ledger mutations.

## 3. Mobile AI Command Center Architecture

The PWA delivers full feature parity with the desktop AI ecosystem:

| Capability | Desktop Web Experience | PWA / Mobile Experience | Backend Architecture |
|---|---|---|---|
| **AI Copilot** | Right slide-over panel with drag-to-resize | Full-screen & bottom sheet with voice input & touch controls | Same 23 backend tools (19 read-only, 4 action proposals) |
| **Input Methods** | Text prompt + quick prompt chips | Text prompt + 🎙️ Web Speech Voice input | Unified `/api/assistant/chat` endpoint |
| **6 Operational Agents** | 3x2 desktop grid in Agent Control Center | 1-column responsive mobile cards with Quick Run/History | Unified `/api/agents` & `/api/portfolio` endpoints |
| **Daily AI Briefing** | KPI summary overview | Interactive sequential Priority Review workflow | Real-time MySQL aggregation & Groq LLM |
| **Action Proposals** | Desktop review cards | Touch-friendly cards with tactile haptic confirmation | Phase 3 Human-in-the-Loop Confirmation Protocol |
| **Audit Logging** | Desktop compliance ledger | Mobile audit viewer with complete trace hash | Immutable `audit_logs` table |

## 4. Connectivity & Offline State Flow

```text
[User Action]
      │
      ▼
[useOnlineStatus Hook]
      │
      ├── (isOnline === true)  ──► [Dispatch API Request] ──► [Backend RBAC / Audit / DB]
      │
      └── (isOnline === false) ──► [Trigger Warning Haptic] 
                                    ├── Display Offline Banner
                                    ├── Disable Mutation Buttons
                                    └── Block AI Prompt Submission (Inform User)
```

## 5. Web Push Notification & Deep-Linking Pipeline

Push notifications generated by Agent 6 (Notification & Escalation Agent) follow a deep-linking pattern into specific entity contexts:

```text
Push Notification Received (e.g. Critical Escalation on Case #16)
               │
               ▼
User Taps Notification on Device
               │
               ▼
PWA Opens and Resolves Deep-Link Context
               │
               ▼
Action Center AI Dashboard Loads
               │
               ▼
AI Copilot Automatically Opens with Context = { case: 16 }
               │
               ▼
Accountant Reviews Evidence & Confirms Action
```
