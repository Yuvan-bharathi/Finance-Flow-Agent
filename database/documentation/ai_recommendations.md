# AI Recommendations Table Documentation

## Purpose
Stores matching candidate proposals, confidence scores, and reasoning summaries generated by Groq Payment Reconciliation Agent.

## Columns

| Column | Type | Nullable | Key | Purpose |
|---|---|---|---|---|
| `id` | INT UNSIGNED | NO | PK | Unique recommendation ID |
| `reconciliation_case_id` | INT UNSIGNED | NO | FK | Foreign key to `reconciliation_cases.id` |
| `recommended_company_id` | INT UNSIGNED | YES | FK | Suggested company FK ➔ `companies.id` |
| `recommended_loan_id` | INT UNSIGNED | YES | FK | Suggested loan FK ➔ `loans.id` |
| `recommended_schedule_id` | INT UNSIGNED | YES | FK | Suggested schedule installment FK ➔ `repayment_schedules.id` |
| `confidence_score` | DECIMAL(5,2) | NO | — | AI confidence percentage (0.00% – 100.00%) |
| `reasoning` | TEXT | NO | — | Detailed explanation of signals used by AI |
| `status` | ENUM | NO | — | Candidate state (`pending`, `approved`, `rejected`, `overridden`) |
| `reviewed_by` | INT UNSIGNED | YES | FK | User who reviewed candidate FK ➔ `users.id` |
| `reviewed_at` | TIMESTAMP | YES | — | Timestamp of review |
| `review_comment` | TEXT | YES | — | Human reviewer notes / override reason |
| `created_at` | TIMESTAMP | NO | — | Candidate creation timestamp |

## Relationships
- **N : 1 with `reconciliation_cases`**: Belongs to a case (`ai_recommendations.reconciliation_case_id` ➔ `reconciliation_cases.id`).
- **N : 1 with `repayment_schedules`**: Recommends an installment (`ai_recommendations.recommended_schedule_id` ➔ `repayment_schedules.id`).
- **N : 1 with `users`**: Reviewed by an accountant (`ai_recommendations.reviewed_by` ➔ `users.id`).

## Used By
- AI Reconciliation Agent (`reconciliationAgent.js`), React Action Center UI.

## Mentor Questions

### Q1. Why does `ai_recommendations` store candidate fields rather than directly updating `repayment_schedules`?
**Answer**: To enforce our strict **Human-in-the-Loop** safety architecture. The AI agent acts purely as an intelligent decision-support assistant; official financial ledger changes occur only after human accountant verification.
