FinanceFlow AI — Antigravity Development Manual
1. Project Development Rule

You are building FinanceFlow AI, an Agentic AI-powered financial operations platform.

The application must be developed as a real full-stack production-style project, not as a collection of disconnected demo pages.

The project should use:

Frontend: React
Backend: Node.js + Express.js
Database: MySQL
AI: Groq API
Authentication: JWT + HTTP-only cookies
Authorization: RBAC
Real-time: WebSocket
File Upload: Local/cloud-ready storage abstraction
API Documentation: Swagger/OpenAPI
Testing: Unit + API/integration testing
Deployment: Production-ready configuration

The primary business workflow is:

Company
   ↓
Loan
   ↓
Repayment Schedule
   ↓
Incoming Payment
   ↓
Payment Reconciliation Agent
   ↓
Search / Analyze Financial Data
   ↓
AI Recommendation
   ↓
Confidence Score
   ↓
Human Review / Approval
   ↓
Payment Allocation
   ↓
Outstanding Balance Update
   ↓
Audit Log
2. MOST IMPORTANT RULE — CODE MUST BE LEARNABLE

Do not generate code only for functionality.

Every important piece of code must be written so that a developer who is learning the project can understand:

What the code does
Why it exists
Where the data comes from
Where the data goes
What parameters are received
What each parameter means
Where each parameter originated
What the function returns
Which function calls it
Which function it calls
What happens if it fails

The code should be understandable by reading it from top to bottom.

3. COMMENTING STANDARD

Comments must be useful, not excessive.

Do NOT write comments like:

// Create student
const student = await Student.create(req.body);

This comment adds almost no value.

Instead explain the data flow:

// req.body comes from the JSON payload sent by the frontend.
// Example:
// {
//   "name": "ABC Technologies",
//   "email": "abc@example.com"
// }
//
// The controller passes this object to the Company model,
// which validates the data against the Mongoose/ORM schema
// before creating the database record.
const company = await Company.create(req.body);

33. FINAL RULE — TEACH WHILE BUILDING

The most important instruction:

Do not optimize only for finishing the application. Optimize for the developer understanding the application.

When there is a choice between:

Short but difficult code

and

Clean, structured and understandable code

choose the second.

When a design pattern is introduced, explain:

Why we need it
What problem it solves
Why we selected it
What alternatives exist

When data moves between layers, explain:

Where it started
How it was transformed
Where it went
Why it was transformed

When a React prop is used, explain:

Who passed it
Why it was passed
What value it contains
Where that value originally came from

When an API is called, explain:

Who called it
What data was sent
How the backend received it
Which middleware processed it
Which controller handled it
Which service processed it
Which database operation happened
What response came back
How the frontend used the response

When an AI agent runs, explain:

What triggered the agent
What information it received
What tools it has
Why it selected a tool
What data the tool returned
How the result was given back to the model
What recommendation was generated
Why human approval is required
What backend operation happens after approval


Before implementing any major feature, first show me the proposed architecture, folder changes, data flow, database interaction, API flow, and files that will be created/modified. Do not immediately write the code. After implementation, update the relevant .md documentation and explain the code flow. Do not silently introduce new libraries, architecture patterns, database tables, API endpoints, or major dependencies without documenting why they are needed.
