2. The most important separation
We have three different concepts.
Expected money
Stored in:
repayment_schedules
Example:
Due:
₹1,00,000
Actual money
Stored in:
payments
Example:
Received:
₹75,000
Final accounting decision
Stored in:
payment_allocations
Example:
₹75,000
allocated to
ABC Technologies
Loan #LN001
Installment #5
This separation is very important.

9. What makes this "Agentic AI"?
This is something your mentor may ask.
We're not simply doing:
User → Prompt → AI → Answer
Our agent will have a goal and tools.
Conceptually:
PaymentReconciliationAgent
          │
          ▼
      New Payment
          │
          ├── Search company
          │
          ├── Search active loans
          │
          ├── Search repayment schedules
          │
          ├── Check historical payments
          │
          ├── Detect possible duplicate
          │
          ├── Calculate candidates
          │
          └── Generate recommendation
                    │
                    ▼
              Human Approval
So the AI agent is taking multiple steps to solve a business task, rather than simply generating text.
We'll implement the actual agent workflow later using Groq API.

12. One small improvement before SQL
I recommend adding one more concept to the schema:
payment_sources
Why?
Because eventually your application may receive payments from:
Bank CSV
Bank API
Manual entry
UPI statement
Excel upload
Instead of hardcoding the source into different places, we can track:
source =
 bank_import
or
source =
 manual
This will make your payment ingestion module more realistic.
However, we do not need another table for this. We can simply add:
source ENUM(
    'bank_import',
    'manual',
    'api',
    'excel_upload'
)
to payments.
