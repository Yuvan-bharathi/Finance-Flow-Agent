Important business rule
A payment 
can be allocated to multiple installments
.
Example:
Payment = ₹1,50,000
Could become:
payment_allocations
Payment #1001
      │
      ├── Installment #101 → ₹1,00,000
      │
      └── Installment #102 → ₹50,000
So:
payments
   │
   │ 1:N
   ▼
payment_allocations
   │
   │ N:1
   ▼
repayment_schedules
This is why we 
cannot simply put 
schedule_id
 inside 
payments
.
That would only allow one payment → one installment.
Our design supports:
One payment → multiple installments.

One important rule before SQL
There is one thing I want us to enforce when we create the actual schema:
Financial records should never be physically deleted casually.
For example, we shouldn't allow an accountant to simply:
DELETE FROM payments;
because this destroys financial history.
Instead, we should use appropriate statuses / audit records for operational changes.
